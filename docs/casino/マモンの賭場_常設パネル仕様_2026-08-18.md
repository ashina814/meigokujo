# マモンの賭場 — 常設パネル仕様（2026-08-18）

本書は `マモンの賭場_大型アップデート_最終実装仕様書_v1.0.md` §12「`/賭場` UI」の追補である。
2026-08-18 以降、`/賭場` の役割、カテゴリ内の常設パネル、公開1v1募集通知は本書の内容を現行仕様とする。

## 1. 入口の原則

- `/賭場` は **個人用の総合ホーム** とする。残高・福分け状態を見ながら、基本ゲームと施設系機能へどこからでも入れる。
- `/賭場` から **公開1v1・競馬・板は開始しない**。公開投稿を伴う機能を通常の個人ホームから切り離す。
- 公開1v1と競馬は、それぞれの専用常設パネルを入口とする。
- 板は `賭場 · 板` の専用常設パネルに加え、独立 slash command `/板` も入口として残す。
- カテゴリ内では、1枚の総合パネルへ全機能を詰めず、用途別の常設パネルを設置する。
- 常設パネルは既存の `casino:home:*` 処理へ接続し、ゲーム・金銭処理を複製しない。
- `/通行証` と `/板` は独立 slash command として残す。
- `/遊ぶ` `/福分け` `/番付` `/賭場商店` `/競馬` `/案内` `/vip` `/流れ星` `/勝負` は再登録しない。
- ルーレットは基本ゲーム側に残すが、30秒間ほかの利用者も参加できる公開卓である点を画面上で明示する。

## 2. 常設パネル

### `賭場 · 遊ぶ` (`casino_games`)

スロット / 丁半 / クラッシュ / チンチロ / ルーレット / BJ / ポーカー / ホールデムの入口。

基本操作は本人向け画面で進むが、**ルーレットだけは30秒間ほかの利用者も参加できる公開卓**なので、「ひとり遊び」とは呼ばない。

### `賭場 · みんなで勝負` (`casino_pvp`)

公開1v1募集専用。
ゲームと賭け金を決めると同じチャンネルへ3分間の募集カードを投稿し、最初に受諾した1人と成立する。
募集時点では資金を預からず、成立時に既存のEscrow・残高・DailyRisk検証へ接続する。
募集通知ロールが設定されている場合だけ、募集カード投稿時にロール通知を送る。

### `賭場 · 競馬` (`casino_keiba`)

競馬専用。既存の競馬処理へ接続する。

### `賭場 · 板` (`casino_ita`)

賭け板作成専用。既存の板処理へ接続する。
独立 slash command `/板` も引き続き利用できる。

### `賭場 · 施設` (`casino_facility`)

商店・通行証・番付・福分け・VIP・流れ星等の施設系入口として維持する。

## 3. `/賭場` 個人ホーム

`/賭場` には次を残す。

- 基本ゲーム選択
- 直前ゲームの再実行
- 商店
- 通行証・戦績
- 番付
- 福分け
- VIP
- 流れ星
- Landへの引き出し
- 遊び方

次は `/賭場` のボタンとして表示しない。

- みんなで勝負
- 競馬
- 板

専用パネルが同じ `casino:home:*` 実処理を再利用するため、内部ルーター自体は削除しない。

## 4. みんなで勝負 募集通知ロール

運営設定 `casino_pvp_notify` に、公開1v1募集時に通知するDiscordロールを設定できる。

- 有効な通知ロールは **最大10ロール**。
- 重複IDは除外する。
- 投稿時の `allowedMentions.roles` は、その投稿で実際に通知する設定済みロールIDだけに限定する。
- `@everyone` / `@here` を許可しない。
- 常設パネル本文には具体的な設定ロール名を焼き込まない。設定変更後に古い表示が残るためである。

### 通知頻度

通知制限は**募集者ユーザー単位**で数える。

1. 同一ユーザーは短時間の3募集連続までロール通知を送る。
2. 3回目の通知直後、そのユーザーは5分間のクールダウンへ入る。
3. クールダウン中は、そのユーザーが出す募集のロールメンションだけを省略する。
4. 募集カードそのものはクールダウン中も通常どおり投稿する。
5. 別ユーザーの募集通知には影響しない。同じ通知ロールを使っていても独立して扱う。
6. ゲーム種別が変わっても、短時間に同じ募集者が続けて募集した場合は同じ3回枠を使う。
7. 前回通知から5分以上空いた場合は連続回数をリセットする。
8. クールダウン経過後は再び3募集連続まで通知できる。
9. Discordへの募集カード送信に失敗した場合は、通知回数を消費しない。
10. 同一募集者の投稿処理中は次の投稿を開始せず、同時操作による二重カード・二重通知を防ぐ。

募集成功後、募集者本人には次のいずれかを表示する。

- 通知を送信した
- 通知は5分クールダウン中で、募集カードだけ投稿した
- 通知ロールが未設定で、募集カードだけ投稿した

5分だけの短時間荒らし抑止なので、通知回数の状態はBotプロセス内に保持する。Bot再起動時には通知クールダウン状態をリセットする。金銭・募集状態・Escrowの永続性には影響しない。

## 5. 変更しないもの

- `/賭場` コマンドそのもの。
- `/板` の独立 slash command。
- 公開1v1の3分募集時間。
- first accepter の成立規則。
- Escrow / Land / チップ / DailyRisk / DB schema。
- 各ゲーム・競馬・板の実処理。

このパネル分離および通知制限では、金銭処理を変更しない。
